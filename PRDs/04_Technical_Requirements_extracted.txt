Architecture OverviewCivicLens is a web-based, client-server application composed of a React front end (Citizen Dashboard, Government Dashboard, and public marketing site), a Node.js backend API, Supabase as the primary backend-as-a-service (Postgres database, authentication, and file storage), and an AI processing layer accessed via OpenRouter for classification, duplicate detection, and multilingual understanding. Map rendering and geolocation are handled client-side via Leaflet with OpenStreetMap tiles.At a high level: Citizen/Officer clients → Node.js API layer → Supabase (Postgres/Auth/Storage) + AI pipeline (OpenRouter) → back to clients via REST/websocket-driven status updates.2. AI Processing PipelineEvery complaint passes through the following pipeline stages before reaching a department queue:1. Input normalization — voice is transcribed and translated as needed; image(s) are validated and stored.2. Computer vision classification — images are analyzed to detect issue type (e.g., pothole, garbage, waterlogging, damaged infrastructure) and contribute to the category suggestion.3. Multilingual NLP classification — text/transcribed content is classified for category and summarized for officer review, via models accessed through OpenRouter.4. Duplicate detection — combines geospatial proximity (radius search on latitude/longitude) with content/image similarity scoring against open complaints in the same area; complaints above a similarity threshold are flagged for citizen/officer confirmation before creating a new record.5. Priority scoring — combines issue severity classification, population density of the reported location, and local complaint recurrence to produce a priority score used to rank department queues and flag &quot;critical&quot; complaints.6. Department routing — maps the classified category to the correct IMC department/sub-branch per the routing table defined in the Features &amp; Requirements document.7. Human-in-the-loop review — all AI suggestions are presented to the receiving officer for accept/override before a complaint is formally accepted into a department’s active workload; overrides are logged to ai_suggestions for future model improvement.5. Authentication &amp; Access ControlSupabase Auth handles identity for both citizens and government users, with role stored on the users table (citizen, officer, admin).Row-Level Security (RLS) policies in Postgres enforce that citizens can only read/write their own complaints, officers can only access complaints routed to their department, and admins have city-wide read access plus write access to department/SLA configuration.All AI-suggestion overrides and status changes are attributed to the acting user_id for auditability.7. Location &amp; MappingLeaflet renders the interactive map for complaint pin placement (citizen side) and complaint density/heatmap views (admin analytics).OpenStreetMap tiles are the base map layer; a geocoding provider resolves free-text locality search to coordinates and reverse-geocodes device GPS to a human-readable address.All location data is stored as latitude/longitude on the complaints table, with locality/ward name resolved at write time for filtering in analytics.8.
