Design PrinciplesClarity over decoration — civic complaint status must be legible in seconds, especially for low-literacy or low-connectivity users.Trust through transparency — every screen that shows a complaint must show its current status and timestamp.Multilingual-first — layouts must not break when text expands/contracts across languages or scripts (e.g., Hindi vs. English).Consistent premium visual language on the public/marketing surface (dark, glass, motion-forward) contrasted with a utilitarian, data-dense visual language on the operational dashboards.2. Citizen Dashboard — UX Flows4.1 OnboardingLogin/Register → Location permission prompt → (granted) auto-detected area confirmation, or (denied) manual city/locality picker → Language preference selection → Dashboard home.4.2 Submit a ComplaintDashboard home → &quot;Report a Problem&quot; primary action → choose input mode (voice / photo / text, combinable) → confirm/adjust map pin location → AI preview shows suggested category + department (editable before submit) → duplicate-check prompt if applicable → submit → confirmation screen with tracking ID.4.3 Track Complaints&quot;My Complaints&quot; list, grouped by status (Pending / In Progress / Resolved), each card showing category icon, short description, location, submitted date, and current status badge → tap for full timeline detail view with department response, estimated resolution date, and (once resolved) proof photo/notes.4.4 Visual/Interaction NotesStatus badges use consistent color coding across the entire product: Submitted (grey), Accepted (blue), In Progress (amber), Resolved (green), Rejected (red).Voice input uses a large, single-tap microphone affordance with visible waveform/recording feedback for low-literacy accessibility.Map pin adjustment must be usable with one thumb on mobile.5. Government Dashboard — UX Flows5.1 Officer QueueLogin → Department-scoped queue, default sorted by AI priority score (critical items pinned to top with a distinct red/amber marker) → filter/search by category, location, or SLA aging → open a complaint to view AI Copilot suggestion (category, department, priority, rationale), citizen-submitted media, and map location.5.2 Complaint ActionAccept (set/confirm estimated resolution time) or Reject (required reason) or Reassign (different department/sub-branch) → on accept, complaint moves to &quot;In Progress&quot; queue → officer can update status and attach resolution photo/notes → mark Resolved.5.3 Administrator Analytics ViewTop-level KPI tiles (Critical Complaints, Pending Complaints, SLA Violations, Avg. Resolution Time) → below, tabbed or side-by-side charts for Complaints by Category, Complaints by Location (map heatmap), Department Workload, and Resolution Time trend → date-range filter applies globally across the view.5.4 Visual Language for DashboardsData-dense, high-contrast, light-mode surface distinct from the dark public marketing hero — optimized for scanning tables and charts over long shifts.Priority and SLA-risk indicators use the same status color coding as the citizen dashboard for cross-role consistency.Map views reuse Leaflet + OpenStreetMap tiles from the citizen-side location picker for visual and technical consistency.6. Accessibility &amp; Multilingual UIAll interactive elements meet minimum touch-target sizing for mobile use in the field.Text and UI labels support Hindi and English at minimum, with layout tested for text-length variance between scripts.Voice-first submission path is a first-class flow, not a fallback, to support low-literacy citizens.Color is never the sole indicator of status — icons/labels accompany every status color.
